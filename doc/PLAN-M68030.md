# The AP68060 060-70mhz pipeline as an MC68030

Request (2026-11-03): remake github.com/apolkosnik/AP68060 branch
060-70mhz as an MC68030 and push it to github.com/apolkosnik/AP68030
branch 030-70mhz.  Decisions (the user, 2026-11-03):

- **Bus:** MC68030 pins through AP68030's bus controller (ap030_bus.v:
  S0-S5, dynamic bus sizing, STERM, CBREQ/CBACK bursts, RMC, retry,
  arbitration) behind the pipeline's BIU request interface.
- **FPU:** a parameter.  On: the on-chip FPU with 68881/68882 behaviour
  (no 060 unimplemented-instruction traps, 68882 FSAVE/FRESTORE frames).
  Off: F-line instructions take the 030 coprocessor protocol (CpID 1
  cycles) / the F-line exception.
- **Caches:** a parameter.  Either the 8 KB four-way caches with 030
  behaviour (write-through, CACR/CAAR, the MMU's CI and CIIN), or
  030-exact 256-byte caches (16 lines of four long words, logical tags
  with FC).

The pipeline (fetch, decode, sequencer, AG..WB, the DMU) and its 70 MHz
timing stay; what is 060-specific goes.

## Phases

1. **ISA.**  From the 040 import (1b53c23): CHK2/CMP2, CAS2, MOVEP,
   64-bit MULS/MULU.L and DIVS/DIVU.L, misaligned CAS execute instead of
   vector 61.  MOVE16, CINV/CPUSH, PLPA, LPSTOP, HALT, PULSE go (F-line /
   illegal as on the 030).  MOVEC: SFC, DFC, CACR, USP, VBR, CAAR, MSP,
   ISP; every other number is illegal (vector 4).  The PMMU's cpID 0
   instructions: PMOVE (TC, CRP, SRP, TT0, TT1, MMUSR, with FD), PTEST
   (levels, A register), PLOAD, PFLUSH/PFLUSHA (FC, mask, EA).  CALLM/RTM
   illegal.
2. **Programming model.**  SR.M with a separate MSP (interrupts clear M
   and stack a throwaway frame $1 on the ISP); trace T1 and T0 (change
   of flow); frames $0, $1, $2 (CHK, CHK2, TRAPcc, TRAPV, trace, divide by
   zero: the instruction address), $9 (coprocessor mid-instruction), $A
   and $B (short/long bus fault: SSW, fault address, data buffers); RTE
   of each with the format error rules; bus errors rerun on RTE (SSW DF:
   the instruction is restarted with the faulted access completed from
   the frame when DF is clear).
3. **Bus.**  ap030_bus at the pins; the bench becomes AP68030's
   tb_ap030_program (pin-level slave models, test registers) so its
   programs (t_integer, t_exceptions, t_bus, t_cache, t_mmu, t_cp,
   t_stack, t_snoop, t_extword, t_pmmuenc, t_held, t_dblfault, t_lazy,
   t_cpx_*, t_initstruct, t_ipendmask, dhry) are the regression, with
   the 060 programs that still apply converted.
4. **MMU.**  The 030 PMMU: TC (E, SRE, FCL, PS 256 B-32 KB, IS, TIA-TID),
   CRP/SRP (limit, DT), TT0/TT1, MMUSR; the table search with short and
   long descriptors, early termination, indirect descriptors, limits,
   U/M/WP/CI; the ATC holding failed entries (B), the FC in its tags.
5. **Caches.**  The two variants above, CACR's EI/FI/CEI/CI/IBE and
   ED/FD/CED/CD/DBE/WA, CAAR.
6. **FPU parameter.**  On: 68882 behaviour; off: the coprocessor
   protocol (AP68030's t_cp/t_cpx_* must pass).
7. **70 MHz.**  Out-of-context fits at 14.286 ns; the corpus (WinUAE
   68030, /home/adam/ap68030/cputest030) only with the user's yes.

## Verification

Each phase: the regression of the bench in use, the benchmarks, and the
checks the RTL carries.  The 68030 reference for behaviour questions:
MC68030UM, and AP68030's core (rtl/ap030_*.v), which passes the suite.
